# Adversarial review – v2.0.0-beta.1

- **Reviewed commit:** `812f985df1e38ccdce092f5684080ce5fcfad445`
- **Models:** Claude Opus, Claude Sonnet
- **Reports:** `docs/reviews/v2.0.0-beta.1-claude-opus.md`, `docs/reviews/v2.0.0-beta.1-claude-sonnet.md`
- **Date:** 2026-11-16

The two models reviewed the commit independently, each from a read-only
checkout, with the same brief: the update and signing path first, then
the root helpers, the webUI, the values reaching argv, nft and config
files, the Rust parsers of network traffic, and the systemd sandboxes.
Neither ran the test suites. Each report ends with what it did not
cover.

Each finding was re-checked against the source before it went into this
table. Where the reviewers rated the same issue differently, the severity
below is ours, with the reason.

| ID | Severity | Finding | Status | Sources |
|---|---|---|---|---|
| R1 | high | `publish` signs the SHA256SUMS and tarball the keyless `image` job uploads, without checking the tarball is the one `sign-stage` signed (`.github/workflows/build-installer.yml`, `publish`). Code running in the image job (apt, live-build and QEMU as root) could have the release key sign a tarball of its own, which every router would install, unattended with `update.auto_install_security`. Both reviewers rated it medium; it is high here because it defeats the key isolation the workflow is built around and reaches every router through the update channel. | fixed in the release PR for v2.0.0-beta.1: `publish` downloads `release-signed`, verifies it with the keys the commit ships and refuses unless the tarball is byte-identical (`installer/release_test.go`, `TestPublishSignsOnlyTheTarballSignStageSigned`); docs/RELEASING.md says the ISO's integrity rests on the image job | Claude Opus #1, Claude Sonnet #1 |
| R2 | medium | The update-helper keeps running across an update it installed, and compared requests with the version it was built as (`apply.NewUpdater`): after 2.0.0 → 2.0.2, a second request could install 2.0.1 (SEC-12), record a stale rollback target, and reinstall over the directory in use. Needs an admin session. | fixed in the release PR for v2.0.0-beta.1: the installed version is read per request from the release `/usr/libexec/fr_os` points at (`apply.InstalledVersion`), and replacing the release in use is refused (`apply/update_test.go`, `TestTheInstalledVersionIsTheReleaseInUse`) | Claude Sonnet #2, #7 |
| R3 | medium | A LAN host can forge packets (source address of another host) that get that host quarantined: a ClientHello with a blocklisted JA3/JA4 when `tls_fingerprint.quarantine_on_match` is on, or SNI drops and DNS queries feeding the AI-IDS score. XDP sees the frame before reverse-path filtering. | accepted: the same as 1.x; TLS quarantine is off by default (`quarantine_on_match: false`), and a quarantine expires (at most 7 days). Tracked for 2.0.0: bind the evidence to the source MAC or to an established flow | Claude Opus #2, Claude Sonnet #8 |
| R4 | medium | A request for a locked account still runs scrypt (32 MiB) for equal timing but isn't counted against the source, so one host can lock a name and then send unlimited concurrent sign-ins (`webui/routes.go` `loginSubmit`, `webui/ztna.go`), exhausting memory. | accepted: denial of service of the management plane only, from a host that reaches the management address. Tracked for 2.0.0: count it as a failure, bound concurrent hashes, `MemoryMax=` on the webUI | Claude Sonnet #3 |
| R5 | medium | The webUI's server has no read timeout and reads up to 1 MiB of a body before authentication (`cmd/fr-webui/main.go`, `webui/server.go`): slow-body connections hold goroutines, memory and descriptors. Claude Opus rated it low; medium here, with R4, for a pre-auth denial of service. | accepted: denial of service of the management plane only. Tracked for 2.0.0: `ReadTimeout` with a per-request deadline for the SSE route, smaller pre-auth bodies, a connection cap | Claude Sonnet #4, Claude Opus #4 |
| R6 | low | The self-signed webUI certificate is a CA with no name constraints and 10 years' validity, offered for download to be trusted. | accepted: tracked for 2.0.0 (a leaf certificate, or name constraints) | Claude Sonnet #5 |
| R7 | low | Nothing checks at release time that `release/keys/` holds only the expected keys, and the `release` environment's protection rests on the `v*` tag rule (required reviewers aren't available on the current plan). | accepted: one key is committed and reviewed; required reviewers and a tag ruleset are turned on when the repository goes public (docs/RELEASING.md) | Claude Sonnet #6 |
| R8 | low | `drop_privileges` falls back to `nobody` when `fr_os-sensor` can't be looked up (`crates/fros-xdp/src/privdrop.rs`). | accepted: tracked for 2.0.0 (fail closed) | Claude Sonnet #9 |
| R9 | low | `writePrivate` chowns its temporary file by path between close and rename, in a directory the webUI account owns; a compromised webUI could redirect a root chown during the console's `set-admin-password` / `mfa-reset` (`webui/accounts.go`). | accepted: needs code execution as `fr_os-webui` and a race with the console command. Tracked for 2.0.0 (`f.Chown` on the open file) | Claude Opus #3 |
| R10 | low | A compromised parser daemon can hold the apply-helper's 32 connection slots and stall the webUI's requests (`helper/server.go`). | accepted: needs a compromised sensor daemon first. Tracked for 2.0.0 (slots per peer uid, a short first-byte deadline) | Claude Opus #5 |
| R11 | low | Rollback doesn't compare the target with the running version (`apply/update.go` `Rollback`). | duplicate of R2 | Claude Sonnet #7 |

Status: `fixed ...`, `accepted: <reason>`, `not a bug: <reason>` or
